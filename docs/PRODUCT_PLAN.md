# Full Context Canvas:产品与开发计划

> 你只管收藏。它负责归位、告诉你东西去了哪,并把散落的东西串成新想法。

这份文档配合 `prototype/` 里的可交互原型使用。它分四部分:产品定义、原型演示脚本、技术方案、开发路线。

---

## 1. 产品定义

### 一句话
**你的 AI 只记得你的一部分。Full Context Canvas 让它记得全部。**

### 问题
一个知识工作者的"第二大脑"散落在十几个地方:Claude、ChatGPT、Gemini 的聊天记录,Chrome 书签,YouTube 稍后观看,Reddit 已保存,X 书签。

- 每个 AI 只记得在它自己那里发生的事。让 AI 写简历、做决定、开新项目时,它拿到的只是一小块的你。
- 人不会每天整理。东西每天都在进来,一次性大扫除之后很快又乱了。
- 对 ADHD 和信息过载的人来说,这是根本开不了头的问题。光是想"那个东西在哪"就耗尽了启动的力气。
- 用户不敢把东西交给 AI 整理,因为不知道它会把东西放到哪,怕找不到。

### 解决方案:四条设计原则
| 原则 | 具体做法 | 原型里对应的地方 |
|---|---|---|
| 收藏动作不增加任何一步 | 用户继续在原平台点收藏,我们在后台接住 | 「模拟一条新收藏」按钮:卡片从平台图标飞进对应分组 |
| 永远不搬动原件 | 整理是叠在上面的一层索引,原件留在原平台 | 卡片详情里的「原件位置」和「原件没有被移动」 |
| 每个决定都看得见 | 来源线 + 重叠分组 + 每组一句理由 + 把握度 | 点卡片 → 发光的线连回平台;「为什么在这些组里」 |
| 整理是手段,综合才是产品 | 跨平台生成简历、交汇点、项目资料包,每句带出处 | 底部「问问你存过的全部东西」和「综合」标签页 |

### 透明度机制(核心差异点)
1. **来源线**:点任意卡片,一根发光的线连回它的原平台。证明东西没被搬走,只是被看见了。
2. **重叠分组**:一条收藏可以同时属于多个组,交集区域一眼可见。交集本身就是分组依据,也往往是新想法的来源。
3. **每个决定有理由和把握度**:理由引用内容里的具体线索。把握度低于 60% 的会被标出来,不会悄悄放错。
4. **待确认队列**:AI 拿不准的东西集中给你,一键确认或移出。每次纠正都写进整理记录。
5. **整理记录(可追溯链)**:每张卡片都有一条从"接收 → AI 读取 → 放入"到"你修正"的完整时间线。
6. **盘点**:一共存了多少、在哪些平台、哪些主题横跨了几个平台。

### 目标用户(按优先级)
1. 同时重度使用 2–3 个 AI 助手的知识工作者(设计师、产品经理、研究者、学生)
2. ADHD 和信息过载人群:收藏多、整理少、经常"知道自己存过但找不到"
3. 之后:把"个人 context"开放给其他 AI 工具调用(B 端/开发者接口)

### 竞品对比
| | mymind | Raindrop | Notion / Obsidian | Full Context Canvas |
|---|---|---|---|---|
| 要不要手动存进去 | 要 | 要 | 要 | 不用,接住原平台的收藏 |
| AI 聊天记录 | 不支持 | 不支持 | 手动导入 | Claude / ChatGPT / Gemini 导入 |
| 整理透明吗 | 不透明,只能搜 | 手动为主 | 手动 | 每条有来源线、理由、把握度 |
| 一条能在多个组吗 | 标签可以 | 单文件夹 | 看用法 | 重叠分组是核心视觉 |
| 整理之后 | 结束 | 结束 | 结束 | 跨平台综合生成,每句带出处 |

### 为什么是现在
一两年前大多数人只用一个 AI。现在同时用两三个是常态,**AI 之间的 context 碎片化是这两年才出现的新问题**。每家 AI 都想当中心,没有一家会把竞争对手的记录当一等公民。中立的、跨 AI 的 context 层只能由第三方来做。

## 2. 原型演示脚本(3 分钟)

打开 `prototype/index.html`,或打开发布出来的 claude.ai 链接。右上角 `EN / 中文` 切换语言。

**最省事的方式:点顶栏的「演示导览」**。它把下面的脚本做成了 10 步,每一步自动完成操作并显示字幕,用 `←` `→` 键翻页,`Esc` 退出。把链接末尾加上 `#tour` 再发给投资人,对方打开就直接进入导览,不用你在场。

导览的 10 步:整理前(7 个平台各一列)→ 整理后(飞到一张白板)→ 点卡片看来源线 → 一个平台的全部 → 新收藏自动归位 → 待确认 → 交汇点 → 综合写简历 → 所有出处连回原平台 → 收尾。

画布右上角的「整理前 / 整理后」可以随时切换,适合讲"为什么需要这个产品"的那一刻。

**手动演示时的节奏**

| 时间 | 操作 | 要说的话 |
|---|---|---|
| 0:00 | 停在首屏 | "这是一个人 7 个平台上的 41 样东西:3 个 AI 的聊天记录、Chrome 书签、YouTube、Reddit、X。它们第一次在同一张白板上。" |
| 0:20 | 点「Learn any software in 3 days」那张卡 | "一根线连回 YouTube,原件没动。它同时在学习、AI、设计三个组里,每个组都写了为什么、有多大把握。" |
| 0:50 | 点左侧 Reddit 图标 | "这是 Reddit 上所有收藏,每一条都连回原平台。" |
| 1:05 | 点「模拟一条新收藏」两次 | "用户照常在 X 上点书签,它自己飞进对应的组,右边留下记录。用户不用多做任何一步。" |
| 1:25 | 打开「待确认」,移出一条 | "AI 拿不准的会主动说出来。一键改,改完记进整理记录。敢把东西交给它,是因为看得见它怎么想。" |
| 1:50 | 点底部「帮我写一份简历」 | "现在是真正的价值:它同时读 7 个平台,写出一份简历。每一句都有出处。" |
| 2:20 | 点一个出处编号,再点「在画布上连出全部来源」 | "这句来自 Claude 里的作品集讨论。整份简历用了 16 条来源,来自 7 个平台。任何一个单独的 AI 都做不到。" |
| 2:40 | 点「导入」→「用示例书签文件试试」→「开始整理」 | "真实文件也可以。这是一个真实的书签导出文件,解析、分组、飞入,全在浏览器里完成。" |

**演示前的检查**
- 在 claude.ai 上打开时,如果右上角显示「AI 实时:Claude」,综合和导入会调用真实的 Claude;第一次调用会弹出授权。怕现场网络不稳,就在「综合」页勾选「用离线演示答案」。
- 离线模式下三个示例问题都有预先写好的答案,引用的都是画布上的真实卡片;导入会改用关键词规则,并如实标注"离线规则,不是 AI"。
- 刷新页面即恢复初始演示状态。

## 3. 技术方案(从原型到 MVP)

### 3.1 各平台怎么接入
| 平台 | 方式 | 可行性 | 备注 |
|---|---|---|---|
| Chrome / Edge / Arc 书签 | 浏览器插件 `chrome.bookmarks` API,监听新增 | ✅ 高 | 实时,无需平台授权 |
| Claude 聊天 | 设置 → 导出数据(conversations.json) | ✅ 高 | 批量;增量需要用户定期导出,或插件在网页端捕获 |
| ChatGPT 聊天 | 设置 → 数据控制 → 导出 | ✅ 高 | 同上 |
| Gemini 聊天 | Google Takeout「我的活动」 | 🟡 中 | 导出格式较粗,只有提问,没有完整回答 |
| YouTube 稍后观看 | 插件在用户点「保存」时捕获;存量走 Google Takeout 播放列表 | 🟡 中 | 官方 Data API 读不到「稍后观看」 |
| Reddit 已保存 | Reddit OAuth API 的 saved 列表 | ✅ 高 | 注意 API 使用条款和频率限制 |
| X 书签 | 插件在用户点书签时捕获 | 🟡 中 | 官方书签接口要付费档位,价格常变,成本高 |
| Gmail(第二版) | Gmail API | 🟠 低 | 读邮件属于受限权限,需要 Google 安全审核,周期长 |

**核心判断**:存量靠官方导出,增量靠浏览器插件。插件在用户点击收藏的那一刻接住内容,不依赖平台开放接口。

### 3.2 系统架构
```
┌────────────── 采集层 ──────────────┐
│ 浏览器插件(书签/YouTube/X/Reddit)│
│ 文件导入(Claude/ChatGPT/Takeout)  │
│ OAuth 连接器(Reddit,后续 Gmail)  │
└───────────────┬────────────────────┘
                ▼
        接收队列(每条带来源、原始位置、时间)
                ▼
┌────────────── 理解层 ──────────────┐
│ 内容抓取:标题、摘要、视频字幕、聊天首段 │
│ 向量化(embedding)+ 增量聚类        │
│ LLM 分组:多标签 + 理由 + 把握度      │
│ 低把握度 → 待确认队列                 │
└───────────────┬────────────────────┘
                ▼
┌────────────── 存储层 ──────────────┐
│ Postgres:items / groups / placements / events │
│ pgvector:向量检索                    │
│ 事件表 = 整理记录(只追加,可追溯)    │
└───────────────┬────────────────────┘
                ▼
┌────────────── 应用层 ──────────────┐
│ 白板前端(来源线、重叠分组、语义缩放)│
│ 综合生成(检索 + 带引用的生成)       │
│ MCP server:让 Claude 等工具读取你的 context │
└────────────────────────────────────┘
```

### 3.3 数据模型(关键是"可追溯")
- `Item`:一条收藏的索引卡。`source`、`original_location`、`original_url`、`title`、`excerpt`、`saved_at`。**不存原件副本,只存索引和摘要。**
- `Group`:AI 生成或用户创建的组。`name`、`definition`(这个组收什么)。
- `Placement`:Item 和 Group 的多对多关系。`confidence`、`reason`、`decided_by`(ai / user)。
- `Event`:只追加的事件流。`received`、`read`、`placed`、`user_confirmed`、`user_removed`、`group_created`。原型里的「整理记录」和「整理日志」就是这张表。

### 3.4 AI 部分
- **分组**:先用 embedding 做粗聚类,新内容先匹配已有组;匹配不上再让 LLM 决定是否新建组。每次决定必须输出理由和把握度(原型里 `classifyLive()` 的提示词就是这个格式)。
- **纠正会被学到**:用户的确认和移出作为少样本例子,放进之后的分类提示词里;积累够了再做个性化的阈值调整。
- **综合生成**:检索相关 Item → 带 id 的上下文 → 要求每句引用 id → 前端把 id 渲染成可点击的出处(原型里 `runSynth()`)。
- **成本控制**:分类用快速小模型,综合用强模型。对标题和摘要做分类,不对全文;视频只取字幕前几分钟。

### 3.5 隐私与信任
- 原件永远不动,平台授权一律只读。
- 默认只存索引和摘要;用户可一键删除全部数据,并能导出整理记录。
- 明确告诉用户哪些内容会发给 AI 模型(原型导入弹窗里已经这样写了)。

## 4. 开发路线

| 阶段 | 时间 | 交付 | 验证什么 |
|---|---|---|---|
| **0. 原型**(已完成) | — | 可交互白板 + 演示数据 + 真实文件导入 + 综合生成 | 投资人和用户能不能 30 秒看懂 |
| **1. 可用 MVP** | 6–8 周 | Chrome 插件(书签)+ Claude/ChatGPT 导出导入 + 云端存储 + 白板 + 简历/资料包生成 | 20 个种子用户导入后,第二周还会回来 |
| **2. 持续流入** | +6 周 | YouTube、X、Reddit 实时捕获;每周整理日报;待确认队列 | 用户不再手动整理;每周新增收藏被自动归位的比例 |
| **3. Context 开放** | +8 周 | MCP server:在 Claude、Cursor 等工具里直接调用你的 context | 用户在其他 AI 里调用的频率;付费转化 |
| **4. 扩展** | 之后 | Gmail/教育邮箱、Pocket 等;团队共享画布 | B 端需求 |

### MVP 技术栈建议
- 前端:Next.js + React,白板用 React Flow 或 tldraw 的 SDK 起步,后期换自研 Canvas/WebGL 渲染以支持上千张卡片
- 插件:Chrome Manifest V3(`bookmarks` API + 在 YouTube / X 页面注入内容脚本)
- 后端:Postgres + pgvector(Supabase 可以省掉很多运维),队列用 Inngest 或 BullMQ
- AI:Claude API(分类用快速模型,综合用强模型)
- 认证:Google 登录

### 团队(最小配置)
- 你:产品和设计(透明度体验就是核心壁垒,这是创始人该亲自做的)
- 1 名全栈工程师:插件 + 后端 + 前端
- 可选 1 名兼职 AI 工程师:分类质量评测、成本优化

### 需要提前准备的数据
- **分类准确率**:拿 5–10 个真实用户的收藏,人工标注 300 条,测 AI 分组和理由的准确率。投资人会问"分得准吗",这是最直接的回答。
- **信任指标**:用户对"待确认"的处理率、纠正率随时间下降的曲线。

## 5. 投资人会问的问题

| 问题 | 回答方向 |
|---|---|
| Claude、ChatGPT 自己会做记忆,你怎么活? | 每家 AI 都想当中心,没有一家会把竞争对手的记录当一等公民。跨 AI 的中立 context 层只能由第三方做。 |
| 和 mymind、Notion 有什么不同? | 它们要你主动存进去,我们接住你在原平台已经做的收藏。它们整理完就结束,我们的终点是生成。 |
| 平台不开放接口怎么办? | 存量走官方导出,增量走浏览器插件在点击收藏时接住,不依赖平台接口。 |
| 为什么用户会留下? | 收藏每天都在发生,整理需求是持续的。每周日报 + 综合生成让它变成每周都用的工具。 |
| 谁付钱? | 先做个人订阅(重度多 AI 用户、ADHD 知识工作者);之后把个人 context 通过 MCP 开放给其他 AI 工具,向开发者和团队收费。 |
| 为什么是你? | 创始人本人有 ADHD,同时用 3 个 AI 和 5 个收藏平台,这就是每天的处境。背景是设计师,而这个产品的难点在于让人敢把东西交出去。 |
